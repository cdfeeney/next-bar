### Two notes worth carrying forward

**#3 is the interesting one.** Round 1 correctly made `PendingInviteRedirect`
*peek* so an interrupted navigation could self-heal — but left the destination
page consuming on mount. A handle-less user still lost the plan, because
`OnboardingGate` redirected after the consume had already cleared
sessionStorage. A fix only works if both halves agree on what "arrived" means.
Mounting is not arriving.

**A vacuous test was found by re-running the gate.**
`nightOutsMigration.test.ts` extracted policies with a regex terminating on
`;\n`. Git checks the migration out CRLF on Windows, so it matched ZERO policies
and the criterion-4 non-recursion invariant passed over an empty list. Since the
migration ships unapplied, that static proof is the ONLY thing standing in for
live RLS — a vacuous pass there is precisely the false green this apparatus
exists to catch. Its own `toBeGreaterThan(0)` guard is what surfaced it.
Normalised at the read (`.replace(/\r\n/g, '\n')`) so every pattern in the file
is line-ending agnostic. **Watch for this shape elsewhere: any text assertion
over a checked-out file on Windows.**

An earlier commit in this goal shipped `0051_night_outs_suggest_recheck_before_cap.sql`,
which applied 0050's recheck-before-cap fix to `suggest_night_out_bar`. **It has been
removed.** The goal body authorizes exactly five findings and says the invite race needs

database, so nothing is drifted; it needs its own goal, with its own tier decision and
